Secrets in Actions · Fail-soft

One workflow, explained

on:
  workflow_dispatch: {}          # run by hand to test
  schedule:
    - cron: "0 5 * * *"          # then daily, 05:00 UTC

concurrency:
  group: daily-digest           # never two runs pushing state at once
  cancel-in-progress: false

permissions:
  contents: write               # only what it needs: commit state back

jobs:
  digest:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r requirements.txt
      - name: Run digest agent
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: python digest.py
      - name: Commit state
        run: |
          git add state.json digests/ || true
          git diff --cached --quiet || git commit -m "Daily digest $(date -u +%F)"
          git push

Secrets stay out of the code

API keys and credentials live in GitHub Actions secrets and reach the job only as environment variables for the one step that needs them.

Least privilege

The workflow token can write repository contents and nothing else, because committing state is the only thing it has to do.

Safe to run twice

A concurrency group stops overlapping runs, the commit step is skipped when nothing changed, and a timeout ends a stuck job.

Failures are visible, not fatal

If one source fails, the run reports it in the output and carries on with the rest, so one broken feed does not cost a day of results.

Working with AI

I use AI coding assistants (Claude Code, Codex) every day for implementation, tests and refactoring. I decide the design, review every change, run the tests, and make sure I can explain each part. The pipelines above are where that discipline pays off: CI checks the AI-assisted code exactly as strictly as anything I write by hand.
